
# Architecture Lab 3

Навчальний проєкт із рефакторингу архітектури програмного забезпечення.

## Можливості

- Оформлення замовлень через Checkout.
- Централізоване керування платежами через публічний контракт Payments.
- Два платіжні адаптери: Stripe та Wallet.
- Нормалізовані статуси платежів: `paid`, `processing`, `failed`, `unknown`.
- Вибір платіжного провайдера через `runtimeConfig.paymentProvider`.
- Резервування та повернення залишків через `StockRepository`.
- Розрахунок загальної суми з явно заданими податком і знижкою.
- Автоматизовані тести та перевірка архітектурних меж.

## Вимоги

Потрібен Node.js 22.18 або новіший. Встановлювати сторонні залежності не потрібно.

## Запуск

```bash
npm test
npm start
```

Перевірка архітектурних обмежень:

```bash
npm run check:architecture
```

## Конфігурація платіжного провайдера

У `src/config.ts` можна вибрати провайдера:

```ts
paymentProvider: "stripe"
```

або:

```ts
paymentProvider: "wallet"
```

Обидва адаптери реалізують спільний контракт `PaymentProvider`. Checkout і Orders не повинні залежати від конкретного адаптера.

## Структура

```text
src/
  checkout/       оформлення замовлення
  inventory/      керування залишками
  orders/         життєвий цикл замовлення
  payments/       платіжний контракт і адаптери
  shared/         спільні чисті функції
  config.ts       конфігурація
  database.ts     навчальне сховище даних

tests/             автоматизовані тести
scripts/           архітектурні перевірки
README.md          опис і запуск проєкту
REVIEW.md          аналіз початкової та фінальної архітектури
DECISIONS.md       журнал архітектурних рішень
ADR-001-payments-boundary.md
                   рішення щодо межі Payments
```
